# 开源方案借鉴落地记录（R27）

调研对象与结论见《开源AVG与视觉小说引擎借鉴调研.md》。本轮**不换引擎**，只抄 P0 三条。

| # | 借鉴来源 | 落到站内 | 改动范围 |
|---|---|---|---|
| 1 | Ren'Py / Naninovel / ink 的状态分层 | `STORE_NS` 三命名空间、`STORE_SCHEMA=1`、`storeCheck()`、`storeResetView()` | 存档初始化段后追加，旧键不改名、数据零迁移 |
| 2 | WebGAL / Monogatari 的舞台命令模型 | `STAGE_LOG` + `emitStage()` + `stageLogSummary()`，在 `stageFor / refreshStageCast / queuePerf` 记录 `resolve / apply / perf` | 纯附加语句，只记意图、不重放副作用、不改渲染路径 |
| 3 | 资源清单／哈希／自动化门禁 | `杯雪资源清单.csv/json`（229 层）与 `资源清单门禁.py` | 站外脚本，发布前必跑，退出码 0 才允许打包 |

**命名空间划分**：`progress`（`beixue_games_v1`、`beixue_prog_v1`、`beixue_last_v1`、`beixue_streak_v1`）、`preferences`（模式／难度／四路音控／皮肤／呼吸／震动／演出门槛／天气／气泡透明度等）、`view`（`beixue_spr_v1`、`beixue_bublay_v1`、`beixue_hallbg_v1`、`beixue_layout_v1`）。立绘位置、气泡摆位、场景选择明确划为 `view`——可随时丢弃重建。

**未落地（P1，按报告顺序）**：内容节点图（Twine Passage / ink 会话快照）、版本化快照存档与可截断命令日志、朗读与 aria-live 统一队列、音效图序列化、开发期多文件 + 发布期合并单文件。完整命令解释器会改变 `stageFor/queuePerf/refreshStageCast` 的渲染职责，风险高，排在状态模型稳定之后。
